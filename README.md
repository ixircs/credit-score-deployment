# Credit Score Classification — Local vs. Cloud Deployment

Multiclass credit score classifier (Good / Standard / Poor) with **two parallel
deployment architectures** built to compare trade-offs: a local Streamlit app,
and a cloud pipeline on **AWS SageMaker + EC2**.

## Model

XGBoost pipeline with hyperparameter tuning (randomized search), tracked in
MLflow (SQLite backend — `mlflow.db`). Preprocessing (imputation, encoding,
scaling) is wrapped in a `DataPreprocessor` class shared between training and
inference so the exact same transform runs in both places.

```
data_A.csv
     │
     ▼
data_ingestion.py     load raw data
     │
     ▼
pre_processing.py     DataPreprocessor.clean() + build_transformer()
     │
     ▼
train.py              XGBoost + randomized hyperparameter search
     │
     ▼
evaluation.py          metrics (macro F1, accuracy, per-class)
     │
     ▼
pipeline.py            orchestrates all of the above, logs everything to MLflow
     │
     ▼
model_credit_score.pkl
```

Run the full pipeline: `python pipeline.py`

## Deployment 1 — Local (Streamlit)

`app.py` + `inference.py`: model loaded directly in-process. Form for the
model's 22 input features, plus three preset test cases (Good/Standard/Poor)
for quick testing.

```bash
pip install -r requirements.txt
python pipeline.py        # train + save model_credit_score.pkl
streamlit run app.py
```

## Deployment 2 — Cloud (AWS SageMaker + EC2)

Full architecture, setup steps, and troubleshooting are documented in
[`aws/README.md`](aws/README.md). Summary:

```
model_credit_score.joblib ──tar.gz──► S3
                                        │
     SageMaker real-time endpoint ◄── inference.py (SageMaker contract:
     (SKLearnModel, ml.m5.large)        model_fn/input_fn/predict_fn/output_fn)
                                        │
     Streamlit on EC2 (systemd) ── boto3 sagemaker-runtime ──► endpoint
     (IAM instance profile)                                    public URL :8501
```

The model itself is **not retrained** for the cloud path — same
`model_credit_score` artifact, repackaged as `.joblib` for the SageMaker
container.

## Local vs. Cloud — trade-offs

| | Local (Streamlit + `.pkl`) | Cloud (SageMaker + EC2) |
|---|---|---|
| Latency | Low — model in-process | Extra hop (EC2 → SageMaker endpoint) + cold start |
| Cost | None | Per-hour while endpoint is `InService` |
| Scalability | Tied to one machine | Endpoint can be scaled independently of the frontend |
| Access | Local only (or one Streamlit Cloud instance) | Public URL, IAM-isolated, frontend/model decoupled |
| Setup complexity | Minimal | S3 packaging, IAM role, security group, container framework-version matching |

(Full first-hand comparison, including what actually broke during setup, in
[`POIN_3_Banding_Lokal_vs_Cloud.md`](POIN_3_Banding_Lokal_vs_Cloud.md).)
